# Culling Bay for iPhone

A native SwiftUI app over the photo server's `/m/api` routes (`review/API.md`). The server
on the PC keeps doing everything it does now (NAS, RAW decodes, search, Lightroom). The app is
a better front end. The web pages under `/m` stay as a fallback.

Scope and decisions: https://claude.ai/artifact/FQv95YRVDg1DK6tBvruvob (picks made 2026-10-17).

## Layout

- `CullingBayCore/`: Swift package with no UI. It holds the models, the API client with ETags,
  save options, Server-Timing parsing, timing reports, and zoom tile planning. It builds and tests
  on Linux (the PC) and on the Mac. See its README.
  Screen state lives there too, as `@MainActor @Observable` models, so it is tested on the PC and
  the SwiftUI views stay thin.
- `CullingBay/`: the SwiftUI app target, generated by XcodeGen from `project.yml`, importing
  `CullingBayCore`. The shell is `CullingBayApp`, `RootView` (Gallery, Cull, Practice and People tabs) and
  `SettingsView` (a sheet with Done; the server address is a screen of its own with Save); `Gallery/` has the home, results and viewer screens and the save sheet;
  `Cull/` has the days list, the cards, the burst picker, the focus check and the end-of-day review; `People/` has the
  People tab (see below); `Images/` loads and decodes
  pictures; `Platform/` holds the PhotoKit and UIKit calls; `Shared/` has the (i) sheet of a photo's camera details (ISO,
  shutter, aperture, lens, size, when and where, and the People section), opened from the Cull card, the burst picker and the Gallery viewer. It asks
  the PC when it opens and saves nothing on the phone. `Shared/ConnectionBanners.swift` has the two kinds of offline: the
  orange Work offline capsule (an aeroplane, "Working offline", Go online) at the top of each tab's first screen and of an
  opened day, and the Days list's yellow "Can't reach the PC" line (`wifi.slash`) with Try now.
- People (`CullingBay/People/`, the fourth tab, `person.2`): `PeopleTab` is the navigation stack (`PeopleRoute`,
  `PeopleRouter`) and `PeopleHomeView` its first screen: a "Finding faces… N of M photos" line while the backfill or an
  import runs, a grid of the named people (face crop in a circle, name, photo count, an orange dot when there are
  suggestions to review) and a grid of the groups nobody has named ("Alex?" when one looks like a person, else
  "N photos · M days"), pull to refresh, and a name filter. `PersonScreen` is the big circle, the name, a
  "Review N suggestions" banner (and, under it, a quieter "Maybe not Alex? Check N faces" one when the PC has doubts
  about faces it filed as them, which opens the same review sheet on them, least sure first) and the person's photos as
  the Gallery's `ResultsView` over `FeedModel.Source.person` (viewer and Save included), with a menu to Rename, Merge with…, Manage faces and
  Remove name. A long press on one of their photos (`ResultsView`'s optional `tileMenu`, which only this screen passes, and which is also given as VoiceOver actions and
  is off while the grid is selecting) offers "Not Alex" (`PersonModel.removeFromPhoto`: the tile slides out, their count
  drops and a `PersonToast` with Undo says "Removed Alex from this photo"; with "1/burst" on it takes them off every frame of
  the burst the tile stands for) and "Show faces in this photo" (the (i) sheet). Select on this screen adds a "Not Alex"
  button to the selection bar (`ResultsView`'s optional `selectionActions`, which only this screen passes):
  `PersonModel.removeFromPhotos` takes them off every selected photo in one write and one toast, with one Undo, says
  "Removed Alex from 12 photos" (photos that didn't have their face stay, and are counted in the toast). `GroupScreen` is
  the same for a group (Add name, "Is this Alex?" Yes/No, Not someone I know) over `.group`. `ReviewSheet` is "Is this
  Alex?" (or, from the second banner, "Maybe not Alex?") on a grid of large crops (a tap puts a red ✕ on one, "None are
  Alex" puts one on every face and then reads "Clear all", Confirm sends the batch and loads the next). `ManageFacesView`
  is a person's faces with Select, Not Alex, Move to… and Not a face, and a long press for Make cover and Show photo.
  `PersonPickerSheet` is the one picker for naming, moving, merging and "This is…". `PhotoPeopleSection` is the (i)
  sheet's People section: each face in the photo with a menu (Not Alex, This is…, Not a face). Face crops are `GET /m/api/face/<id>` through the same `RemoteImage` and
  loader as the thumbnails. People needs the PC and keeps nothing on the phone: offline it shows the Work offline capsule or
  the "Can't reach the PC" line with Try now, and a write that cannot be sent says so. `-CBStartTab people` and
  `-CBOpenPerson <id>` open it in the simulator (`LaunchOptions`).
- Being offline: `AppServices` owns a `ServerLink` (CullingBayCore), rebuilt with the rest by `setServer`. It probes the PC
  at launch (`launch()`), when the app comes to the front, when the phone's network changes (`Platform/NetworkPathWatcher`,
  `NWPathMonitor`) and on Try now or a pull of the Days list; while the PC cannot be reached every request fails at once
  and saved days answer from the phone. Reaching the PC again sends the taps waiting, syncs the saved days, refreshes the
  days list and reloads a Gallery or Practice screen that had failed; an open Cull day is left alone. Work offline is a
  switch in Settings > Offline, kept in `UserDefaults` as `offlineForced` until it is turned off.

## Building on the Mac (Monday)

The PC writes the code; the Mac compiles it over SSH. The Mac is `100.64.156.37` on Tailscale
(ssh with `-o HostKeyAlias=192.168.1.75`).

1. Check `xcodebuild -version`, and install XcodeGen (`brew install xcodegen`) if it's missing.
2. Run `swift test` in `CullingBayCore` on macOS as well.
3. Build the app without signing, then package an .ipa for the phone's re-signing tool:

       xcodegen generate
       xcodebuild -project CullingBay.xcodeproj -scheme CullingBay -configuration Release \
         -sdk iphoneos -archivePath build/CullingBay.xcarchive archive \
         CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
       mkdir -p build/Payload && cp -R build/CullingBay.xcarchive/Products/Applications/CullingBay.app build/Payload/
       (cd build && zip -qr CullingBay.ipa Payload)

4. Simulator screenshots (`xcrun simctl io booted screenshot`) let the screens be checked before an install.

Info.plist needs:
- an App Transport Security allowance for plain HTTP to the PC (N4);
- `NSPhotoLibraryAddUsageDescription`, because saving asks only for add-only access to Photos.

A free Apple ID allows a limited number of app IDs, so phase 4's widget (an app extension with an
App Group) needs checking against Danny's re-signing setup before it's built.

## Delivering a build

Run `ios/build-ipa.sh` on the PC once the app target and `ios/project.yml` are present.
It copies `ios/` to the Mac, builds an unsigned .ipa, and brings it back to
`~/photo-culling/trial_out/ios`. It keeps five builds.

```sh
ios/build-ipa.sh --dry-run
ios/build-ipa.sh --test
ios/build-ipa.sh --test --screenshot
ios/build-ipa.sh --host user@addr --out /path/to/ios
```

`--test` runs the core tests on the Mac first. `--screenshot` also tries an iPhone simulator
and saves `CullingBay.png` beside the builds. A screenshot failure does not block delivery.
`--dry-run` only prints commands. The build number is the PC's Git commit count; rebuilding
the same commit replaces that build. New commits are needed for new build numbers.

On the phone, open http://100.82.57.4:8000/m/ios/ and download `CullingBay.ipa`.
Share → SideStore, or open it from Files in SideStore. SideStore re-signs it with the free Apple ID.
This URL is the delivery destination for the open question above.

To try source updates, add http://100.82.57.4:8000/m/ios/source.json in SideStore.
SideStore may refuse a plain-HTTP source; check this on the phone. Check installation,
launching, and update detection after a later build too. The source uses the latest build's
version and build number; older kept files remain linked from the download page.
